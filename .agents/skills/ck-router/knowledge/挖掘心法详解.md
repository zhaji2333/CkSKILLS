# 挖掘心法详解

> 所属：全局能力（非单一漏洞类型）。摘要见 `../../../../rules/15-hunting-mindset.md`。
> 这份不是流程，是"如何看见别人看不见的机会"的判据；流程见 `../../../../rules/70-routing.md` 与 `进站决策.md`。

## 一、漏洞嗅觉：把"异常"当线索

**观察维度**（每个请求都顺手看一眼）：

| 维度 | 异常信号 → 动作 |
|---|---|
| 时间 | 同参数不同值响应耗时差异大（盲注/后端处理分支）→ 做基线差分 |
| 体量 | 返回大小突变、分页 total 异常 → 布尔/注入差分 |
| 措辞 | 报错文案从模板 A 变模板 B、出现 SQL/堆栈/框架名 → 转注入/信息泄露 |
| 状态码 | 401→200、403→302、405 后换方法/路径又通 → 鉴权差异 |
| 字段 | 字段数/字段名变化、多了 id/内部字段 → 越权与新接口线索 |
| 数据形状 | 空数组、null、缺字段、重复键、类型从 str 变 array → 参数污染/类型混淆 |
| 缓存 | 同一 URL 不同人拿到不同内容、X-Cache 时有时无 → 缓存类问题 |

**硬纪律**：异常先记录（线索板 §2/§4），再做**对照实验**（正常 vs 异常、有权限 vs 无权限、改前 vs 改后）；没有对照不下结论。

## 二、开发者视角：先测最可能偷懒的地方

优先清单（命中即先测）：

1. **新功能**：上线三个月内的业务，鉴权/校验常是后补的。
2. **内部/调试接口**：`/internal`、`/debug`、`/actuator`、`/swagger`、`/test`、`/openapi`。
3. **批量操作**：批量删除/导出/改状态，单条校验了、批量往往没校验。
4. **旧版本 API**：`/v1`、`/v2`、老域名、老 H5、移动端专用接口（前端已不调用但后端还在）。
5. **错误分支**：故意触发异常，看是否绕过后续校验直接成功。
6. **管理后台**：只跳 SSO 但后端仍有账密/接口；前端隐藏的菜单会被后端 API 暴露。
7. **第三方回调/webhook**：签名校验是否真验、能否伪造。
8. **导出/下载**：文件名、路径、id 常直拼；导出常绕过分页权限。
9. **定时任务/队列**：触发条件可猜、任务参数可污染。

## 三、信息收集要"脏"：把公开面挖到边界

| 来源 | 产出 |
|---|---|
| 历史快照（Wayback/archive） | 旧路径、旧参数、已删除接口 |
| 代码托管搜索 | 内部域名、密钥、测试账号、私有 API 命名 |
| 搜索引擎 dork | 目录列表、报错页、备份文件、文档 |
| 证书透明度 | 子域名、内网命名规律 |
| 招聘 JD | 技术栈、内部系统名、中间件 |
| JS 注释 / source map | 接口路径、参数名、密钥、隐藏路由、演示账号 |
| robots / sitemap / .well-known | 管理路径、备份、api 前缀 |
| APK/IPA | 移动端专用 API、硬编码 key、环境域名 |
| Changelog / 更新日志 | 新功能与修复描述常直接暴露漏洞点 |
| 兄弟域 / 同 IP / 同证书 | 未做同等防护的业务面 |
| 备案 / 工商 / 公开信息 | 全资子公司域、业务别名 |
| 公开对象存储 / 错误页 / 备份 | 源码、配置、凭据 |

**纪律**：线索当轮写入线索板；不把"扫到多少资产"当产出，只有"进入清单并可测"才算。

## 四、跨接口关联五问：单点低危 → 组合提级

拿到一个点后，强制过五个问题（答"是"就继续串）：

| # | 问题 | 例子 |
|---|---|---|
| ① 信息流 | A 接口泄露的数据能否喂给 B 接口？ | 列表泄露内部 id → 详情接口换 id 越权 |
| ② 凭证 | 一处拿到的 token/key/cookie 能否用于另一处？ | 前端硬编码 key → 调管理接口 |
| ③ 状态 | A 改的状态 B 是否信任？ | 订单状态接口 → 支付回调直接发货 |
| ④ 权限 | 低权面能否产出高权接口的输入？ | 普通用户可写配置 → 管理端读取执行 |
| ⑤ 时序 | 先做 A 再做 B 能否绕过校验？ | 先领券再改价 / 先创建再改归属 |

**提级原则**：单点低危（信息泄露/缺校验）本身不报高危，先串链；串不上再按实际影响定级。

## 五、覆盖度自检：每轮收尾必做

```
✅ 已测（有结论，含"无漏洞"结论 + 否定证据）
❌ 未测（写原因：无入口 / 无差分面 / 被拦且绕过到 L4 仍失败）
🔄 变种（同点的其它编码/位置/参数/顺序，计划下一轮）
💡 关联（可串的接口、凭证、状态、时序）
```

变种思维清单：URL/HTML/Unicode/UTF-16 编码、类型（str/int/array/object）、注入点位置（query/body/header/path）、执行顺序、大小写与双写、参数名与字段名（含 JS 里的真名）。

## 六、可利用性六问（定级与报告前必答）

1. **稳定复现**：Yes/No（按需重试若干次；环境/时序敏感要注明）。
2. **前置条件**：需要登录？什么角色？什么网络位置？特定版本/配置？
3. **影响面**：数据泄露 / 资金 / 权限提升 / 横向 / 持久化（写清楚"能读到谁的什么"）。
4. **攻击成本**：低/中/高（是否需要受害者交互、是否需要内网、是否需要已知信息）。
5. **修复优先级**：P0/P1/P2（按影响面与利用难度）。
6. **现有缓解**：WAF/风控/审计/限速是否实际拦住某个环节（拦住了就降级或写限制）。

**纪律**：六问答不全的，只能写"疑似/待验证"，不得写进正式报告的"已证实"。
