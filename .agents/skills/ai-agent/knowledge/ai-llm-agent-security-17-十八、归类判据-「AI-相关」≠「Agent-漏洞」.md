# 十八、归类判据：「AI 相关」≠「Agent 漏洞」

> 来源：CkSKILLS v1 `ai-llm-agent-security` §十八、归类判据：「AI 相关」≠「Agent 漏洞」（迁移至 v2 知识块）

> 形态：base64 注入 → AI 原样输出 → 原样入库 → `marked`→`innerHTML` 无净化 → 免登录分享传播 → 官方域存储型 XSS。

**判据只有一句话：看危害闭环的最后一步落在哪一层。**

| 判断项 | 是 Agent 类漏洞 | 不是（属 Web / LLM 输出类） |
|---|---|---|
| 危害落在哪层 | **运行时/执行层**：Shell、文件、HTTP、云凭证、沙箱、集群 | **前端渲染层**：HTML/JS 在浏览器执行 |
| 模型的角色 | **自主决策者**：自己选工具、拼参数、多步执行 | **确定性函数**：解码/翻译/复述/格式化文本 |
| 能力是否被武器化 | ✅ 注入了工具的**选择权与参数**（越权调用、越权参数） | ❌ 只是蹭了它的**输出通道**绕检测 |
| 典型编号 | LLM06 过度授权/工具滥用、LLM03 供应链 | **LLM05 不当输出处理** |

**六条自检（命中"是"才按 Agent 类申报）**
1. 有工具调用吗？（`exec`/代码解释器/文件读写/HTTP/SQL/浏览器）
2. 注入能改变**工具的选择或参数**吗？还是只改变**文本内容**？
3. 危害需要浏览器渲染才成立吗？→ **需要则不是 Agent 漏洞**
4. AI 只是"解码/复述"吗？→ **是则不是**（它是通道，不是能力）
5. 换个非 AI 的存储点（评论/昵称），这条链还成立吗？→ **成立则属 Web 类**
6. 影响面靠什么放大？靠**分享/渲染**（Web）还是靠**工具越权/跨租户**（Agent）？

**常见误判**：把"LLM 帮我绕过了 WAF/过滤器"当成"我打穿了 Agent"。**绕过检测层 ≠ 武器化能力层。** 前者是攻击者的**技巧**，后者才是被攻击系统的**缺陷**。
- 该案例的真实缺陷在四处**Web 层**：① WAF 只覆盖输入通道 ② 输出未净化即入库 ③ 前端 `marked`→`innerHTML` 无 DOMPurify ④ 分享链接免登录取内容
- 正确归类：`xss-frontend-security` 第四节（AI/Markdown 渲染型存储 XSS）→ 定级走 XSS 口径（域内执行 + 免登录传播 = 严重）
- **升级线索**：同一系统若另有工具调用面，单独探测并**另开报告**——不要混在一份里
