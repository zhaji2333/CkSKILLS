# 二十二、接口发现陷阱

> 来源：CkSKILLS v1 `ai-llm-agent-security` §二十二、接口发现陷阱（迁移至 v2 知识块）

### 陷阱 1：大小写不一致导致整个模块漏测

**形态**：按驼峰 `getUserProfile` 探测全 404，判定模块不存在；chunk 的 import 链里真实路径是全小写 `getuserprofile`，一次暴露整组接口。

**规则**：探测路径时必须生成**大小写变体**，尤其是驼峰命名：
```
getUserProfile / getuserprofile / get-user-profile / GetUserProfile
openClaw  / openclaw  / open-claw
userId / userid / user-id / UserID
```
**更可靠的做法（优先用这个）**：不要靠猜，**顺着 chunk 的 `import` 链找 API 封装模块**。
```bash
grep -oE 'from"\./[A-Za-z0-9_.\-]+"' page-chunk.js
grep -oE 'url:\s*[`"][^`"]+[`"]' xxxApi.js
```
> API 封装模块（`*Api.js`）通常**不含业务逻辑、只含端点定义**，是提取接口面的最优目标。

### 陷阱 2：`/api/xxx/*` 前缀级过滤器会让路径探测完全失效

**形态**：同一前缀下多条猜测路径（含明显不存在的）全部返回同一句 403。说明存在**前缀级鉴权过滤器**，在路由匹配之前就拦截。

**判定**：若同一前缀下**所有**猜测路径返回**完全相同**的 403，则：
- 该前缀受统一保护（真实存在的端点无法用状态码区分）
- **不要据此判定端点存在**（不存在的也会 403）
- 转向：① 找真实前端 chunk 确认路径 ② 找该前缀的正确大小写 ③ 换服务

### 陷阱 3（补充）："能创建凭据" ≠ "能利用"

**形态**：创建接口能生成 API 密钥、列表还回明文，但拿这把 key 调模型推理口返回已失效/无权限。

**规则**：拿到凭据后**必须实测它的能力边界**（能否真正调用目标资源、能调用什么），否则会把"功能可用"误报成"漏洞可利用"。

**同时注意**：测试性创建的资源（密钥/账号/任务）**用完必须清理**，并在报告中记录清理动作。
