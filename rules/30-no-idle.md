# rules/30 — 不空转 / 不堆假点 / 失败升级

> 目标：把"时间与请求浪费"降到最低，把"假点污染报告"降到零。

## 禁止的空转

> 换层/停止看信号与边际收益，不按固定次数：任何「X 次就停/换」都只是启发式默认值，现场可改。

1. 问"要不要继续 / 下一步您看 / 还要我挖吗"——有 pending 就直接干；确实全 done 就汇报结论后继续下一条线索。
2. 用扫描数量/请求数量当产出（空扫凑数）。
3. 同一手法原地重试：同一层反复无新证据就换层；换层看新信号/新解释，不凑次数。
4. 反复读同一知识库块 / 反复重扫已证伪的 Host、路径。

## 失败升级（Level 1→7 是维度清单，可按现场跳层；换层时说明已试什么、为什么换）

| Level | 动作 |
|---|---|
| L1 | 编码（URL/HTML/Unicode/UTF-16/双重编码） |
| L2 | 变形（大小写/分隔符/空白/等价函数/截断） |
| L3 | 逻辑（顺序/参数污染/类型混淆/边界值/多值） |
| L4 | 协议（分块/压缩/头部/Host/HTTP2/方法） |
| L5 | 换入口（同业务另一接口/另一 Host/移动端 API/旧版本） |
| L6 | 组合（低危拼接/链式利用） |
| L7 | 时间维度（竞态/重放/延时/缓存） |

**"无此功能/无漏洞"结论不能只试一两种就下**：把适用维度过一遍，写明已试维度与否定证据；不要求凑到某一层。

## 假点判定（命中任一 → 不报，最多记入线索板"假设"）

- 数据本来就是公开的 / 只返回自己的数据
- token/会话已过期或只是占位串
- 只能列不能读、只能读自己前缀、403 与 200 边界不清
- 无跨主体差分（换 id 结果一样）
- 环境报错伪装的"报错注入"（如 DB 未连上导致 500）
- 扫描器误报（未人工复核）

## 每轮收尾（硬性）

- 读线索板 → 更新"当前焦点"与"下一步"
- 列出本轮：✅已证实 / ❌已证伪 / 🔄变种 / 💡关联
- 未进板的线索不算本轮完成
