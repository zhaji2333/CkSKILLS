# rules/20 — 最小伤害红线

> 只约束**副作用**，不约束测试覆盖面。隔离实验环境/容器可放宽，仍禁打平台与其他租户。

## 动作顺序

1. 只读验证（GET / 查询 / 列目录）优先，能证明就停。
2. 需要写：只写自己能回收的测试对象；最小化（1 条、1 次、小文件）。
3. 需要改现成对象：只改可回滚的测试字段，改完立刻改回；改不回就停在回包证据。

## 绝对禁止（即使授权也默认不做，除非用户明确要求）

- 登出 / 注销 / 吊销令牌（`/logout`、`/signout`、`/revoke`），以及"退出后会话是否仍有效"测试
- 删除/修改他人已存在的数据（订单、地址、密码、角色、权限）
- 改密/改绑/改角色后不回滚
- 批量拉取真实用户 PII（证件号/银行卡/大规模手机号）；作业必需的凭据/密钥不在此列（见下）
- 真实资金操作（扣款、清库存、真实下单支付）
- DoS 压测、打挂生产、持久化后门（除非任务明确要求且环境隔离）

## 凭证与敏感数据处理

1. **作业凭据一律存原文**：账号口令、密钥/Secret、Token/JWT、Session/Cookie、内部地址、库连接串、API Key —— 写入线索板 `§5`，供继续利用；这是线索板的核心价值。长期不用/失效的移入「失效」并注日期。
2. **报告写完整实值**：正式报告按 `rules/40-evidence-report.md` 写凭证/账号/会话的完整实值（审核需要复现）；**对外公开/分享材料**才去实值并用占位。
3. **真实用户 PII 最小化**：证件号、银行卡、完整手机号等只取证明所需的最少样本（报告危害举例 1–2 条即可证明），不批量拉取、不扩散；对外公开/分享材料去实值。
4. 线索板/raw 只留本地工作区，不提交到公开仓库。

## 例外判断

隔离实验环境/容器：允许一次性写入与命令执行（以证明影响为准，拿完证据即停），仍禁止攻击平台本身或其他租户环境。
