# rules/66 — 并行、子代理与线索板回灌

> 多 agent 的唯一硬要求：**开工读板，收工回灌；回灌不落板 = 这轮没干。**
> 写者唯一：`CLUEBOARD.md` 只由 Lead 写，teammate 只写自己的 `dig/<角色>/`。
> 理由：跨轮记忆靠板不靠会话上下文；上下文一断、会话一换，没落板的产出等于没挖过。

## 一、角色与写域

| 角色 | 写域 | 禁止 |
|---|---|---|
| Lead | `CLUEBOARD.md`、`报告/`、`dig/lead/`、`raw/` | 把无证据推断写成已证实 |
| teammate | `dig/<角色>/`（脚本/日志/`SYNC.md`） | 写板、写 `报告/`、碰别人的 `dig/` |

- spawn 前在 prompt 写死三件事：**读板哪几节**、**写域**、**交付物（必须含 `SYNC.md`）**。
- 写域重叠 = 互相覆盖 = 记忆丢失；同一文件禁止两人写。合板能力是并发上限，合不过来就少开。

## 二、子代理三动作

1. **开工读板**（只读）：§0 焦点 / §1 Host / §4 已证伪 / §6 待办；已证伪的不重测。
2. **干活留证**：结论/脚本写 `dig/<角色>/`，原始响应写 `raw/<角色>/`；板里只留指针。
3. **收工回灌**：写 `dig/<角色>/SYNC.md`（模板 `templates/TEAMMATE-SYNC.template.md`），回灌块正文 `send_message` 给 Lead。

## 三、回灌块（固定 5 行，缺一不可）

```
HOST: <新 host/入口/指纹> | 证据: <相对任务根路径>
PATH: <路径/方法/状态/鉴权> | 证据: <相对任务根路径>
KEY : <密钥/协议/算法/字段/凭证> | 证据: <相对任务根路径>
DEAD: <已证伪/已排除> | 证据: <相对任务根路径>
NEXT: <下一步 + 优先级> | 依据: <板内哪行 / 哪份产物>
```

- 没有新信息写 `N/A — 原因`；禁止"已完成""见文档"这种无信息行。
- 每行只放 1 条结论；整块 ≤30 行；长表进 `dig/`，板上只留路径。
- 凭证实值可进 `KEY` 行或板 §5（作业记忆），但不进正式报告。

## 四、Lead 合板三闸（每轮收工必做）

1. **抽查**：按证据路径抽 1 条核对，防编造、防把推断写成已证实。
2. **落板**：按归属写 §0/§1/§2/§3/§4/§6/§7；只写判断 + 出处，不复述长表。
3. **记账**：`§8 同步日志` 加一行：时间 / 来源 / 合并到哪节 / 未采纳原因。

- 硬判定：`CLUEBOARD.md` mtime 必须 **晚于** 全部 `dig/*/SYNC.md`；否则回灌未完成。
- 子代理产出没进板 = 下一轮从零开始（"丢板等于没挖过"对多 agent 同样成立）。

## 五、检查（收工前一条命令）

```bash
python3 tools/clueboard_sync_check.py hunts/<目标>   # 有未回灌/缺块 → 非零退出
```

无脚本时最低标准：`ls -lt hunts/<目标>/CLUEBOARD.md hunts/<目标>/dig/*/SYNC.md`，板必须最晚。

## 六、例外与边界

- 单人任务：不启用本节，按 `rules/60`。
- 用户要子代理直接写板：按**节**切分（一人一节，禁止同节并发），写前声明"我写 §X"，Lead 复核；仍建议补 `SYNC.md` 留痕。
- 子代理卡死/失败：Lead 拿它的 `dig/` 自行合板，不重开任务、不丢已有产物。
- 收工/换站的索引拟进写 `DONE.md`（见 `线索表与迭代落盘`）；日常回灌用 `SYNC.md`，不混。
