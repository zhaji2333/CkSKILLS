# rules/40 — 漏洞报告规范（唯一口径）

> 本文件是**报告的唯一规范**：写前两道闸、三档定级、标题口径、正文版式、接口清单/复现包格式、落盘命名、不写清单。
> 对话内快速结论可用摘要；**正式交付只认本文件**。报告里的凭证写**完整实值**（审核要能复现），对外公开/分享材料才去实值。

## 一、写前两道闸（不过闸不落盘）

**1）匿名闸**：标题要写「匿名」前先确认——打通那一包有没有 Cookie、这次作业有没有登录态。
- 无登录态打通 → 才可写「匿名/匿名未授权」；描述里用「我没登录」说事实。
- 有登录态 → 禁止写「匿名」；动他人对象写「越权」，描述用「我拿自己的会话」；Cookie 写完整实值。
- `credentials:omit` 通了 ≠ 没登录，不能算匿名。

**2）认钥闸**：抄到密钥/Token/连接串**不算洞**，必须"生产认了"才写。
- 过闸 = 假值对照生产确认 + 认钥枪**带出身份或列表**（SSH：假钥 Permission denied、真钥 Hello 用户名）。
- 私钥/PEM/SSH/AKSK/Token/JWT/库连接串/能当别人用的会话，全部先过闸；没过不写。
- 第一枪已带出身份 → 再补一枪**不影响线上**的只读例；再打会动线上 → 一枪也交（前提仍是已带出身份或列表）。

## 二、三档定级（只写中危/高危/严重；拿不准不写）

| 档 | 判定条件（命中至少一条） |
|---|---|
| **严重** | 命令跑起来；进了别人的号，或改掉别人的密码/绑定（人账号真登录出会话算这里，不归高危）；钱真转走，或录用/理赔/放行这类状态真被改变 |
| **高危** | 对得上自然人（手机/身份证/银行卡/证件照）；云密钥/Token/库连接串/能当别人用的会话（须过认钥闸，且未用于进号转钱）；注入出了他主体的数据；他人未公开的业务正文（内部知识库、未上架/未发布详情、工单正文这类，且是正文不是标题摘要） |
| **中危** | 有权限扩大或业务敏感，但上面两档一条都没中 |

- 个人空间日记/说说/相册，过权限墙只出标题或摘要 → 中危。
- 禁止"比上一份多一个字段就跳档"；定级只对上述条件，不按感觉。

## 三、标题口径（一行说清"谁的站 + 做成了啥"）

- 格式：`<目标/系统> <匿名未授权|越权|任意|批量> <漏洞类型> <结果>`。
- 「匿名」= 打通时没有登录态；有登录态禁止写「匿名」。
- 未登录 + 拿到他人数据 → 同时写「匿名未授权」和「他人」，不写「越权」。
- 有会话 + 动他人对象 → 写「越权」，可带「他人」。
- 能批量 → 带「任意」或「批量」。
- 禁止：有登录态写「匿名」；没登录态写「越权」；用「未登录」顶「未授权」。

## 四、正文版式（固定块，顺序不变）

1. **漏洞标题**：一行，按第三节口径。
2. **目标网站URL**：`目标网站URL：https://…`（人打开的那个站）。
3. **漏洞等级**：中危 / 高危 / 严重（只写一档）。
4. **漏洞描述**：标签单独一行、冒号后换行再写。第一人称大白话讲"我做成了什么"：没登录态写"我没登录……"；有会话写"我拿自己的会话……"。禁止说明书腔（"该接口未做鉴权即可调用"）、禁止"攻击者"。可提链条，但不贴接口表。**硬编码/凭证/密钥类：描述里必须写完整实值 + 完整 JS 地址（http(s) 全路径）**。
5. **漏洞危害**：标签单独一行、冒号后换行。只写最终伤害（人、号、钱、内部正文、能改能删），按拿到的身份/钥的真实权限写全，不按复现打了几枪裁；每种伤害单独一行；**必须有例子**（泄露举 1–2 条实值样例：姓名/手机/地址/证件或内部标题；证明过改动的举改成了什么）；没打过的权限面（能删/能退款）照写伤害，但不编具体"删了谁"。
6. **涉及接口清单**：只列复现步骤里真打过的接口，1/2/3 编号；每条写完整地址 + 出处（JS 附完整 JS 链接、页面附文档 URL）；抄参用的 JS 只作该接口出处，不单列；对照口、没打的口不列。
7. **复现步骤**：1/2/3 逐条，一步一个整包，审核能顺着打完。只为抄参/做对照/看一眼页面的包不成步；对照写在**同一步**描述里，不另开步；参数从哪份 JS/哪个字段抄的写在该步并附完整出处；纯数字遍历不用解释来源；步骤里不写回包、不写"预期"；解密/签名结果单独成步（写怎么跑、解出什么、下一步用它干什么）；认钥/进号放第一步（假值对照写在该步），且该枪必须已带出身份或列表。
8. **整包格式（步骤内）**：每步只贴一个可复制整包；`Host` 紧挨请求行下一行；`Accept`/`Accept-Language: zh-CN`/`Accept-Encoding: gzip, deflate`/`User-Agent: <常见浏览器UA>`/`Connection: close` 写齐；有 body 加 `Content-Type`/`Content-Length`/`Cache-Control: no-cache`；页面有的 `Origin`/`Referer` 写上；**没登录态不写 Cookie；有登录态 Cookie 写完整实值**（禁止挖时带会话、交报告拿掉 Cookie 再标匿名）；包结束直接 `＃`，不贴回包。
9. **修复建议**：贴合该漏洞、精准可落地，简短直白。
10. **排版**：标题/目标URL/等级各占一行、中间不空行；描述、危害冒号后换行；危害每种一行；大块之间单独一行全角 `＃`（禁半角）；复现步骤逐条换行、条间一行 `＃`；复现结束一行 `＃` 接修复建议；不出现多余空行。
11. **落盘**：任务根 `报告/` 下，文件名 = 漏洞标题 + `.md`；不散落到任务根/上级目录；按平台要求统一换行（Windows 用 CRLF）。

## 五、不写清单（命中任一条 → 不写；也不向用户报"低危 xxx"）

半条链；弱口令没进号；无密钥壳（含无账密的 DSN/health/版本）；凭证没过认钥闸（只抄到字符串、没假值对照、认钥枪带不出身份/列表）；进了号但没有身份或列表的只读例；占位/过期/真假同一句错；手机号加解密钥（前端 AES/SM4/RSA 加解密手机的 salt/iv/密钥）；仅 up/down；低危/信息级/配置提醒/证书过期（无利用链）/缺安全头；CORS；未授权发短信/邮件/验证码；滑块/无限试密没进号；本职可读、本账号权限内、公开运营数据、指纹、临时 OSS 图链、公开说明文；只害自己的 CSRF；接口 200 有 JSON；拿不准。

## 六、重复与升级

- 同一漏洞（同类型 + 同 URL，换 id/多带参仍算同一条）→ 不重复写；同 URL 不同类型、不同 URL 同类型 → 照写。
- 同一条挖大了 → 改原篇，不另开。
- 中危确认后**先升链**（同一对象没走到写/跨用户/接管/可执行就先跟），升不上去再按中危落盘；确认即写，禁止攒到最后。
- 报告成稿前先读线索板「已证实」行；只有 `假设` 状态的不进报告。

## 七、凭证与 JS 的存放

- **报告**：写完整实值（账号口令/密钥/Token/Cookie/连接串）+ 完整 JS 出处，供审核复现。
- **线索板**：存原文，供继续利用（`rules/60-scope-iteration.md`）。
- **战法索引/知识块**：只写形态与方法，**禁止**收录密钥实值、完整 JS 原文。
- **对外公开/分享材料**：一律去实值（占位），并说明"实值见内部报告"。
