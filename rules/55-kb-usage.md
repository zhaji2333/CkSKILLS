# rules/55 — 结构化数据层（kb/）使用纪律

> 数据在仓库根 `kb/`（CVE / 字典 / 载荷），不是技能正文。用它的目的是**少猜、少编**，不是多读。

## 1. 什么时候查

| 场景 | 动作 |
|---|---|
| 要写 CVE 编号、影响版本、修复版本 | 先 `kb/vuln/INDEX.md` 定位，再读单条；事实以厂商公告/NVD 为准 |
| 要找口令/目录/子域/端口/路径字典 | `kb/dict/INDEX.md`（有行数/用途/标签） |
| 要构造 payload（XSS/SQLi/SSRF/上传/反序列化…） | `kb/payload/INDEX.md` |
| 不知道有没有覆盖 | 先 `grep -ril "<产品/关键词>" kb/vuln/`，再开命中文件 |

不确定时加载 `kb-security-data` 技能包（含分诊表与证据纪律）。

## 2. 检索纪律（省上下文）

1. **先 INDEX 后单条**：INDEX 是压缩表；命中再开文件。
2. **禁止通读** `kb/`、禁止 `ls -R kb/`、禁止一次开多个 CVE 条目"浏览"。
3. **只取需要的行段**：字典用 `sed -n '1,100p'` / `shuf -n 50`；不把大文件整篇读进上下文。
4. 同一文件当轮不重复读；结论写线索板或报告，不留在对话里。

## 3. 证据纪律（报告红线）

- CVE 事实以**厂商公告/NVD** 为准；`kb/` 条目与官方冲突时按官方写，并记录差异。
- PoC 必须**本地复现**才可写进报告；未复现只能标"疑似/待验证"。
- 字典/载荷是原料不是证据；报告只写"用了哪类字典/载荷 + 命中结果"。
- 禁止把 `kb/` 里他人的 PoC 直接贴进交付物而不复现。

## 4. 维护

- 数据变更后：`python3 tools/kb_index.py`；一致性校验：`python3 tools/kb_index.py --check`
- 索引为生成物，禁止手改
- 体积约 37MB；仓库要瘦身时优先剔除 `kb/dict` 下 >1MB 的大表（先看 INDEX 里的行数），删除后重跑脚本


## 5. 与线索板的配合

- 查到的 CVE/字典结论，写线索板时带 `kb/vuln/<分类>/<ID>.md` 这类相对路径当证据指针；
- 未命中的查询记一行"查过 kb：<关键词> 无结果"，避免下一轮重复查。
