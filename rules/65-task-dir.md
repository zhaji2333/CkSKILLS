# rules/65 — 任务目录与清理

> 一个任务 = 一个任务根，起手就建、产出分夹、续跑同根。位置默认 `hunts/<目标短名>/`（或用户指定路径）。

## 一、任务根结构（开新任务必须建齐）

```
hunts/<目标短名>/
  README.md      ← 任务说明、目录结构、进度、续跑命令
  资产/          ← 公网可挖 URL / 域名 / 入口清单（自由跳含 SEEDS.md 种子队列）
  js/            ← 从站点提取/下载的 JS 源文件（分析用）
  报告/          ← 正式报告（文件名 = 漏洞标题，见 rules/40）
  dig/           ← 脚本、队列/状态、findings、日志、临时探测
  CLUEBOARD.md   ← 单目标线索板（模板 templates/CLUEBOARD.template.md）
  raw/           ← 大段原始响应/整份配置（报告与线索板用指针引用）
```

## 二、硬规则

1. **一任务一根目录**：起手先建，再开始产出；禁止把报告/脚本/资产散落在任务根或上级目录。
2. **资产 vs js 分清**：`资产/` 只放公网可挖 URL/域名/入口清单；提取的 `.js` 一律进 `js/`；**JS 绝不进资产**。
3. **报告只进 `报告/`**：文件名 = 漏洞标题 + `.md`（见 `rules/40`）。
4. **dig 只放过程物**：脚本、队列、状态、日志、临时探测；有分析价值的正式提取件移入 `js/`。
5. **续跑/多轮/增量**：仍进同一任务根，不另开散文件；先读 `hunts/<目标>/README.md` 与 `hunts/<目标>/CLUEBOARD.md` 的当前焦点。
6. **用户指定路径时以用户为准**；未指定用上面的默认结构。

## 三、清理口径（用户说"清理"时）

1. 先看 `报告/` 是否有正式报告文件。
2. **无报告** → 整个任务根删除（含 资产/js/dig/README/CLUEBOARD/raw）。
3. **有报告** → 只保留 `报告/` + `资产/` + `CLUEBOARD.md`；删除 `dig/`、`js/`、`raw/`、README（或按用户指示保留）。
4. 只处理任务根；**不得**把工具目录、资料夹、他人文件当任务根误删。
5. **禁止**清理浏览器/系统里保存的账号密码、登录态、他人凭据；任务内的临时 Cookie 文件可随 `dig/` 删除。

## 四、自检（开任务 / 交报告 / 清理前）

- [ ] 任务根是否已建齐 README + 资产 + js + 报告 + dig + CLUEBOARD？
- [ ] JS 是否只在 `js/`，没混进 `资产/`？
- [ ] 报告是否只写在 `报告/`，文件名=标题？
- [ ] 过程脚本/日志是否只在 `dig/`，没散落到桌面或上级目录？
- [ ] 清理时是否先点了 `报告/` 有没有文件？有没有误删报告/资产？
